# SaaS connector command contracts

Use this map to translate an approved behavior into a specific documented command; verify each linked article and the project's installed SDK input/output types. The [vendor command index](https://developer.sailpoint.com/docs/connectivity/saas-connectivity/connector-commands), [SDK command enum](https://github.com/sailpoint-oss/sp-connector-sdk-js/blob/32c520ae4c675079a9f599286674079a34686fe8/lib/commands/command.ts) and runtime spec are different evidence. Do not infer platform support merely from an SDK export. For interceptors see [customizers](customizers.md).

| Requirement | Documented command / decision points |
|---|---|
| Establish connection | [Test connection](https://developer.sailpoint.com/docs/connectivity/saas-connectivity/commands/test-connection): validate configuration and use a safe, meaningful read; identify what it does and does not prove about permissions. |
| Aggregate or refresh accounts | [Account list](https://developer.sailpoint.com/docs/connectivity/saas-connectivity/commands/account-list) emits account objects; [account read](https://developer.sailpoint.com/docs/connectivity/saas-connectivity/commands/account-read) returns one. Reconcile keys, status, relationships, paging and missing records across both. |
| Discover account schema | [Account discover](https://developer.sailpoint.com/docs/connectivity/saas-connectivity/commands/account-discover): verify dynamic discovery is required and supported in the intended source. |
| Aggregate/read entitlements | [Entitlement list](https://developer.sailpoint.com/docs/connectivity/saas-connectivity/commands/entitlement-list), [entitlement read](https://developer.sailpoint.com/docs/connectivity/saas-connectivity/commands/entitlement-read): specify type, identity and membership representation separately. |
| Create or update account and access | [Account create](https://developer.sailpoint.com/docs/connectivity/saas-connectivity/commands/account-create); [account update](https://developer.sailpoint.com/docs/connectivity/saas-connectivity/commands/account-update). Map the actual create policy and update changes to target operations, including partial failure and retry. |
| Account lifecycle | [Enable](https://developer.sailpoint.com/docs/connectivity/saas-connectivity/commands/account-enable), [disable](https://developer.sailpoint.com/docs/connectivity/saas-connectivity/commands/account-disable), [delete](https://developer.sailpoint.com/docs/connectivity/saas-connectivity/commands/account-delete), [unlock](https://developer.sailpoint.com/docs/connectivity/saas-connectivity/commands/account-unlock): decide target state, no-op semantics, retained access and reversibility separately. |
| Credentials | [Authenticate](https://developer.sailpoint.com/docs/connectivity/saas-connectivity/commands/authenticate), [change password](https://developer.sailpoint.com/docs/connectivity/saas-connectivity/commands/change-password): implement only when required and supported; prevent secrets in logs/fixtures. |
| Configuration and discovery | [Config options read](https://developer.sailpoint.com/docs/connectivity/saas-connectivity/commands/config-options-read), [application discovery list](https://developer.sailpoint.com/docs/connectivity/saas-connectivity/commands/application-discovery-list), [source data discover](https://developer.sailpoint.com/docs/connectivity/saas-connectivity/commands/source-data-discover), [source data read](https://developer.sailpoint.com/docs/connectivity/saas-connectivity/commands/source-data-read). Confirm schema, permissions and invocation conditions. |

## Critical contract checks

- The account list article shows individual `res.send` outputs rather than one array, and recommends streaming/pagination to manage time and memory. Ensure list and single-read map the same account and relationships.
- The create and update articles show that a multi-valued entitlement may arrive as a scalar for one value or an array for several. Validate the installed SDK and actual provisioning contract; test both, malformed values, missing required fields and empty/null separately.
- The reviewed SDK defines update operations `Set`, `Add` and `Remove` in [std-account-update.ts](https://github.com/sailpoint-oss/sp-connector-sdk-js/blob/32c520ae4c675079a9f599286674079a34686fe8/lib/commands/std-account-update.ts). Interpret each against the target API: `Set` can replace an entire collection; don't accidentally remove unrelated access. Do not turn unknown, partial or ambiguous outcomes into success.
- SailPoint's [account-read](https://developer.sailpoint.com/docs/connectivity/saas-connectivity/commands/account-read) and [error handling](https://developer.sailpoint.com/docs/connectivity/saas-connectivity/in-depth/error-handling) pages describe `NotFound` as potentially triggering account creation during provisioning. Emit that type only for a confirmed absent target account, never for authorization, timeouts, ambiguous lookup, incomplete pages or other failures. Verify actual provisioning behavior in controlled validation.
- The [account-update article](https://developer.sailpoint.com/docs/connectivity/saas-connectivity/commands/account-update) describes returning an empty object for a no-change outcome and complete state after changes. Do not substitute an integration-specific success/no-op rule: reconcile this guidance with the installed version, source contract and approved requirements, and test it.
- Delta/stateful aggregation requires an approved cursor/checkpoint, deletion and retry strategy; verify the platform's stateful invocation contract and target change feed. Do not advance state before complete successful processing without a justified recovery design.
